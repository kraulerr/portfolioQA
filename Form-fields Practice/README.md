# Тестирование формы с различными полями — Портфолио проект для Manual QA

Этот проект демонстрирует навыки ручного тестирования веб-форм с применением техник тест-дизайна: эквивалентное разбиение, анализ граничных значений, таблица решений, тестирование UI-элементов.

## Цель проекта

Показать умение:
- Применять техники тест-дизайна на практике
- Тестировать форму регистрации интернет-магазина
- Писать чек-листы и тест-кейсы
- Оформлять баг-репорты
- Тестировать валидацию полей и обработку ошибок
- Документировать результаты тестирования

## Объект тестирования

Demo форма регистрации интернет-магазина OpenCart: https://demo.opencart-cms.ru/create-account

**Поля формы (стандартная конфигурация OpenCart):**
- **Имя** (Текстовое поле, обязательное)
- **Фамилия** (Текстовое поле, обязательное)
- **E-Mail** (Email, текстовое поле, обязательное, валидация формата)
- **Телефон** (Текстовое поле, обязательное)
- **Пароль** (Текстовое поле, обязательное)
- **Подтверждение пароля** (Текстовое поле, обязательное)

- **Согласие с политикой конфиденциальности** (Чекбокс, обязательное)
- **Кнопка Продолжить** (Отправка формы)

## Используемые техники тест-дизайна

### 1. Эквивалентное разбиение (Equivalence Partitioning)

Разделение входных данных на классы, где поведение системы ожидается одинаковым.

**Пример для поля E-Mail:**
- Валидный класс: email в правильном формате (test@example.com)
- Невалидные классы:
  - без @ (testexample.com)
  - без домена (test@)
  - пустое значение
  - спецсимволы в начале (!test@example.com)
  - дубликат email (уже зарегистрирован)

**Пример для поля Имя:**
- Валидный класс: текст из букв (Ivan, Petr)
- Невалидные классы:
  - пустое значение
  - только цифры (12345)
  - только спецсимволы (!@#$%)
  - очень длинное значение (33 символа)

### 2. Анализ граничных значений (Boundary Value Analysis)

Проверка значений на границах допустимого диапазона.

**Пример для поля Пароль (требование: 4–20 символов):**
- 3 символа (перед нижней границей) — должно быть ошибкой
- 4 символа (нижняя граница) — должно проходить
- 5 символов (после нижней границы) — должно проходить
- 19 символов (перед верхней границей) — должно проходить
- 20 символов (верхняя граница) — должно проходить
- 21 символ (после верхней границы) — должно быть ошибкой

**Пример для поля Имя / Фамилия:**
- 0 символов (пустое поле) — ошибка (обязательное поле)
- 1 символ — проверка (принимается или ошибка)
- 32 символа (стандартное ограничение OpenCart) — должно проходить
- 33+ символа — проверка (принимается или ошибка)

### 3. Таблица решений (Decision Table)

Используется для проверки комбинаций условий.

**Пример для сценария регистрации:**

| Пароль | Подтверждение | Privacy Policy | Ожидаемый результат |
|--------|---------------|----------------|---------------------|
| Валидный | Совпадает | Отмечено | Регистрация успешна |
| Валидный | Не совпадает | Отмечено | Ошибка: пароли не совпадают |
| Валидный | Совпадает | Не отмечено | Ошибка: нужно согласие |
| Невалидный | — | Отмечено | Ошибка: неверный пароль |
| Пустой | — | Отмечено | Ошибка: поле обязательно |

### Проверки для каждого поля

**Имя / Фамилия:**
- Обязательность заполнения (пустое значение)
- Минимальная длина (1 символ)
- Максимальная длина (32 символа)
- Принятие букв, цифр, спецсимволов
- Принятие кириллицы и латиницы

**E-Mail:**
- Обязательность заполнения
- Валидация формата email
- Принятие email в разном регистре
- Уникальность email (проверка на дубликаты)

**Телефон:**
- Обязательность заполнения
- Валидация формата
- Принятие цифр, букв, спецсимволов
- Минимальная/максимальная длина

**Пароль / Подтверждение пароля:**
- Обязательность заполнения
- Минимальная длина (4 символа)
- Максимальная длина (20 символов)
- Совпадение паролей
- Принятие спецсимволов

**Privacy Policy:**
- Обязательность отметки
- Ссылка на политику конфиденциальности (работает ли)

**Подписка на новости:**
- Необязательное поле
- Влияние на регистрацию (не должно влиять)
